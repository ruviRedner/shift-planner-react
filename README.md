# סידור משמרות דו־שבועי

סידור משמרות עם React, TypeScript ו־Vite, ומצב צוות משותף עם שרת Node.js מקומי. נדרש Node.js 24 ומעלה.

## הרצה

```bash
npm install
npm run dev
```

Vite יציג בטרמינל כתובת מקומית, בדרך כלל `http://localhost:5173`.

### בדיקה של כל היכולות, כולל חשבונות והחלפות

```bash
npm run dev:full
```

הפקודה מפעילה את Vite ואת שרת הצוות (פורט 3080). פתחו את כתובת Vite המופיעה בטרמינל; בדרך כלל `http://127.0.0.1:5173`.

1. במצב המקומי אפשר לבדוק שיבוץ אוטומטי, תצוגה מקדימה וייצוא תמונה מיד.
2. לחצו **אזור הצוות · כניסה לחשבון**. בהפעלה הראשונה צרו חשבון מנהל עם קוד ההתקנה שמופיע בטרמינל תחת `First administrator setup code`.
3. במצב המנהל אפשר להעביר את הסידור הקיים מהדפדפן לשרת באמצעות **העבר סידור מהדפדפן לשרת**, אחרי אישור. לחלופין, הוסיפו צוות ושיבוצים בסידור המשותף.
4. בלשונית **החלפות וחשבונות** צרו הזמנה עבור איש צוות. פתחו אותה בפרופיל דפדפן נפרד או חלון פרטי כדי לבדוק את הצד של המדריך, והגדירו שם משתמש וסיסמה.
5. מדריך יכול לבקש החלפה, מדריך אחר מציע להיכנס, והמנהל מאשר. השיבוץ מתעדכן אטומית בשרת ורק לתאריך המבוקש; הקביעות נשמרת. האזור האישי מציג את התוצאה בתוך כמה שניות.

`npm run dev` ממשיך להפעיל את המצב המקומי בלבד. אין שליחת הודעות או הזמנות אוטומטית לאנשים; המנהל מעתיק את קישור ההזמנה ומשתף אותו בעצמו.

## בניית גרסת Production

```bash
npm run build
```

הקבצים המוכנים ייווצרו בתיקייה `dist`.

להרצת הבנייה יחד עם API הצוות: `npm run server`, ואז פתחו `http://127.0.0.1:3080`. לא נדרש שירות חיצוני כדי לבדוק מקומית.

## מה כבר קיים בפרויקט

- לוח לשבועיים, מראשון עד שבת.
- משמרות צהריים ולילה בימים ראשון עד חמישי, משמרת שישי־שבת ומשמרת לילה במוצ״ש.
- שיבוצים קבועים לפי יום ומשמרת, עם אפשרות להחלפה חד־פעמית.
- רשימת אנשי צוות שנשמרת לשימוש חוזר.
- בחירה של כמה אנשים לאותה משמרת.
- מעבר בין תקופות של 14 ימים בלי למחוק תקופות קודמות.
- העתקת השבוע הראשון לשבוע השני.
- שמירה אוטומטית ב־`localStorage`.
- תצוגת הדפסה מותאמת ל־A4 לרוחב.
- התאמה למסך מחשב ולטלפון.

## שיבוצים קבועים

פתחו את „שיבוצים קבועים בכל שבוע”, בחרו יום ומשמרת, סמנו אנשים ולחצו „שמור קביעות”. אפשר לבחור כמה אנשים ואפשר להגדיר לאותו אדם כמה משמרות בשבוע.

לחיצה על משמרת בלוח ושמירה משנות רק אותה בשבוע שנבחר. גם שמירה ללא אנשים נשמרת כשינוי חד־פעמי. הכפתור „חזור לשיבוץ הקבוע” מסיר את השינוי ומחזיר את הקביעות העדכנית.

בשמירת קביעות האנשים שנבחרו מתווספים למשמרת של אותו יום וסוג בכל התקופות, כולל קודמות, גם במשמרות עם שיבוץ ידני או במשמרות שרוקנו. אנשים שכבר שובצו נשמרים ללא כפילויות. לאחר השמירה אפשר לבצע החלפה חד־פעמית כרגיל; שמירת הקביעות שוב מוסיפה מחדש את הנבחרים לכל השבועות. לביטול קביעות מבטלים את כל הבחירות ושומרים; פעולה זו אינה מוחקת שמות שכבר נוספו לשיבוצים ידניים.

העתקת שבוע מעתיקה גם החלפות חד־פעמיות ומשמרות שהושארו ריקות; משמרות קבועות ממשיכות לעקוב אחר הקביעות. ביטול ההעתקה משחזר את המצב הקודם. ניקוי תקופה מרוקן אותה בלבד, בלי למחוק את הגדרות הקביעות.

## גיבוי, עומס וחוסר זמינות

- **הורד גיבוי** שומר קובץ JSON עם כל התקופות, אנשי הצוות, הקביעויות, ההערות וחוסר הזמינות.
- **שחזר מגיבוי** בודק את מבנה הקובץ ואת הקשרים בין הרשומות, מציג תקציר ומבקש אישור לפני החלפת הנתונים. גיבויים קודמים ללא חוסר זמינות נתמכים. מגבלת קובץ: 10MB.
- **סיכום עומס בתקופה המוצגת** מציג לכל אדם את מספר משמרות הצהריים, הלילה ושישי־שבת. מוצ״ש נכלל בלילות; שישי־שבת נספרת פעם אחת. הספירה כוללת קביעויות והחלפות בפועל.
- **חוסר זמינות וחופשות** מאפשר להגדיר טווח תאריכים כולל יום ההתחלה והסיום, עם הערה. ההתראות מופיעות בלוח ובחלון השיבוץ גם עבור קביעויות. שישי־שבת נבדקת מול שני הימים. ההתראה אינה מבטלת את השיבוץ ואפשר לשמור אותו במכוון.
- **בטל פעולה אחרונה** משחזר שיבוצים, קביעויות, אנשי צוות, הערות וחוסר זמינות; גם ניקוי תקופה ושחזור מגיבוי ניתנים לביטול. נשמרות עד 30 פעולות במהלך פתיחת הדף; רענון מאפס את היסטוריית הביטול. הקלדה רצופה באותה הערה היא פעולה אחת. ניווט בין תקופות אינו מוסיף פעולה להיסטוריה, וביטול מחזיר לתקופה שבה בוצעה העריכה.

## בדיקות

נדרש Node.js 24 ומעלה לבדיקות יחידה ב־TypeScript ללא שלב קומפילציה נפרד.

```bash
npm test
npm run build
npm run test:e2e
```

בדיקות הדפדפן רצות ב־Edge ללא חלון גלוי, עם שרת תצוגה בפורט 4173 ושרת API מבודד בפורט 3081. נתוני הבדיקה נכתבים ב־`test-results`, ולא בקובץ הצוות האמיתי. ניתן לבחור דפדפן Chromium מותקן באמצעות משתנה הסביבה `PLAYWRIGHT_CHANNEL`. הבדיקות מכסות גם הרשמה עם הזמנה, כניסה, בקשת החלפה ואישור בין שלושה חשבונות, PNG אמיתי ו־ICS.

## שיבוץ אוטומטי חכם

הכפתור **שיבוץ אוטומטי חכם** פותח הגדרות לכמות אנשים בכל סוג משמרת, תקרת משמרות לאדם בשבוע, מניעת הוספת שתי משמרות לאותו יום ושמירה על משמרות שרוקנו ידנית. ברירות המחדל מוצגות לעריכה לפני יצירת ההצעה: אדם אחד במשמרת, עד שבע משמרות בשבוע, ללא שתי משמרות ביום ושמירה על ריקון ידני.

האלגוריתם משלים חוסרים בלבד, משאיר אנשים שכבר שובצו, מתחשב בחוסר זמינות ומעדיף חלוקת עומס מאוזנת בתקופה ובסוג המשמרת. הוא מטפל קודם במשמרות עם פחות מועמדים. זו הצעה דטרמיניסטית, לא הבטחה למציאת פתרון אופטימלי לכל אילוץ. אם אין מועמד מתאים מוצג חוסר, במקום לשבור את ההגדרות. אפשר לערוך את הבחירה לפני אישור; עריכה ידנית עשויה לחרוג מהעדפות העומס. אישור ההצעה ניתן לביטול.

## תמונה מוכנה לפרסום

**מוכן לפרסום** מציג משמרות ריקות, התנגשויות זמינות והשינויים מאז הגרסה הקודמת. אפשר לייצר תצוגה מקדימה ולייצא PNG באיכות גבוהה, עם שבועיים, שמות והערות שבועיות. התמונה אינה כוללת הערות חוסר זמינות פרטיות. שינויים בשיבוץ מודגשים בצהוב.

כשיש חוסרים או התנגשויות, ברירת המחדל היא תמונת טיוטה. אפשר לאשר במפורש פרסום בכל זאת. הורדת גרסה לפרסום שומרת נקודת השוואה לפעם הבאה, הכלולה גם בגיבוי JSON. שיתוף ישיר פותח את חלון השיתוף של המכשיר, אם הדפדפן תומך בשיתוף קבצים; אחרת מורידים את התמונה ומצרפים לוואטסאפ ידנית.

## האזור האישי והשרת

- למדריך מוצגות המשמרות שלו בתקופה שנבחרה, חוסר הזמינות שלו ובקשות ההחלפה הרלוונטיות. אין לו גישה לנתוני המנהל או להערות הזמינות של מדריכים אחרים.
- **הוסף ליומן** מוריד ICS עם מזהי אירוע יציבים. האירועים הם של יום שלם, כי אין במערכת שעות התחלה וסיום; שישי־שבת מכסה שני ימים. הייצוא הוא קובץ נקודתי, לא מנוי שמתעדכן אוטומטית.
- כניסה משתמשת בססמאות מוצפנות חד־כיוונית עם scrypt ומלח נפרד, ובהפעלות HttpOnly. ההזמנות תקפות לשבעה ימים ולשימוש אחד. המנהל יכול להשבית חשבון ולשלוח הזמנה חדשה; משתמש יכול לשנות את סיסמתו כשהוא מחובר. הפעלה מחדש של השרת מחייבת כניסה חוזרת.
- עדכוני מנהל נשמרים עם מספר גרסה. עדכון מיושן נדחה במקום לדרוס נתונים. במקרה כזה מורידים גיבוי של העבודה המקומית ואז טוענים את הגרסה מהשרת. קליטת שינוי חיצוני מאפסת את היסטוריית הביטול המקומית.
- המנהל רואה הצעות ומאשר או דוחה אותן. האישור בודק מחדש את המשמרת והזמינות, שומר את השינוי ואת תיעוד האישור יחד. מדריך יכול לבטל בקשה או למשוך הצעת החלפה לפני האישור.
- הנתונים המשותפים נשמרים בקובץ `.planner-data/team.json`, שאינו נכלל ב־Git. זהו אחסון אטומי לתהליך שרת יחיד. גיבוי JSON מתוך הלוח כולל את הסידור; לגיבוי מלא של חשבונות, הזמנות והיסטוריית החלפות יש לגבות גם את קובץ השרת.

### הגדרות הרצה

השרת מאזין כברירת מחדל רק למחשב המקומי. `HOST` ו־`PORT` מאפשרים להגדיר כתובת ופורט אחרים. `PLANNER_DATA_FILE` בוחר את קובץ האחסון, ו־`PLANNER_SETUP_TOKEN` מאפשר לקבוע קוד התקנה במקום הקוד שנוצר בהפעלה. `PLANNER_API_TARGET` משנה את יעד ה־proxy של Vite.

לגישה מהטלפונים של הצוות נדרשים שרת נגיש וכתובת משותפת; הגרסה הזו לא פרוסה באינטרנט. בהפעלה מאחורי HTTPS הגדירו `COOKIE_SECURE=1` ו־`APP_ORIGIN` לכתובת המדויקת של האתר. קישורי ההזמנה נוצרים לפי הכתובת שבה המנהל פתח את האתר.

## מבנה הקוד ועקרונות SOLID

- `domain/planner.ts`: טיפוסים, תאריכים והגדרות המשמרות. ימי המשמרת, קטגוריית העומס, צבע ומשך מוגדרים במקום אחד; החישובים צורכים את ההגדרות בלי תנאים נפרדים לכל סוג משמרת (Open/Closed).
- `assignments.ts`, `domain/commands.ts`, `domain/insights.ts`: פונקציות טהורות לחוקי השיבוץ, פעולות וחישוב עומס והתנגשויות, ללא תלות ב־React או בדפדפן (Single Responsibility).
- `storage/codec.ts`: אימות גיבויים והמרת נתונים ישנים. `storage/repository.ts`: ממשק מצומצם `PlannerRepository` עם `load` ו־`save`, ומתאם ל־localStorage (Interface Segregation).
- `Workspace.tsx` ומצב הצוות מזריקים את מתאם השמירה לאפליקציה. ה־hooks תלויים בממשק ולא במימוש localStorage; המתאם המשותף משתמש ב־API, בתור שמירות ובבדיקת גרסה (Dependency Inversion ו־Liskov Substitution).
- `domain/history.ts` מנהל את היסטוריית הפעולות. `hooks/usePlannerStore.ts` מחבר אותה ל־React ולשמירה. `hooks/usePlannerController.ts` מתאם בין פעולות המשתמש לחוקי התחום.
- `components/`: רכיבי תצוגה נפרדים ללוח, חלון שיבוץ, גיבוי, חוסר זמינות וסיכום עומס, המקבלים נתונים ופונקציות דרך props.
- `domain/autoSchedule.ts`, `domain/publication.ts`, `domain/calendarExport.ts`: חוקי ההצעה, ההשוואה לפרסום ויצירת ICS. `export/scheduleImage.ts` אחראי לציור PNG.
- `server/security.mjs`, `server/store.mjs`, `server/teamDomain.mjs`, `server/app.mjs`: הפרדה בין אימות, אחסון, חוקי ההחלפה ונתיבי HTTP. `team/` מכיל את הממשק המשותף והאזור האישי.

היישום משתמש בקומפוזיציה ובממשקים קטנים; אין צורך בהיררכיית ירושה כדי ליישם את העקרונות האלה.

## שינוי סוגי המשמרות בקוד

ב־`src/domain/planner.ts` נמצאת הפונקציה `getShiftsForDay`, המבוססת על הגדרות `SHIFT_META`. שם מוגדרים הימים, הטקסטים, הצבעים וקטגוריות הספירה של המשמרות.

## חשוב לדעת

במצב המקומי המידע נשמר רק בדפדפן שבו האתר נפתח. ניקוי נתוני האתר בדפדפן ימחק את הסידורים המקומיים. מצב הצוות משתמש בקובץ השרת, ושני המצבים נפרדים עד להעברה מפורשת של הנתונים.

אם נתונים קיימים אינם ניתנים לקריאה, האפליקציה מציגה שגיאה ועוצרת שמירה אוטומטית כדי לא לדרוס אותם. אם השמירה נכשלת, למשל עקב מגבלת נפח, מופיעה הודעה להורדת גיבוי.
